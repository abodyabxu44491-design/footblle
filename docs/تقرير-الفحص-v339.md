## 🔴 حرجة

### 1. البطولات الجديدة لا يستطيع منظّمها حفظ أي شيء
`leagueActive()` في القواعد كانت تقرأ `data.locked` مباشرة، لكن `superadmin.js` ينشئ البطولة **بلا حقل `locked`**. وفي Firestore قراءة حقل غائب = خطأ = رفض.
**النتيجة لو نُشرت القواعد:** كل بطولة جديدة، المنظّم لا يحفظ مباراة ولا فريقاً.
اكتُشف بالمحاكي، ولم يكن ليُكتشف بالقراءة. **✅ أُصلح** بـ `.get('locked', false)`، ومثله في `ownsLeague` و`isOwnerUid`.

### 2. XSS مخزّن في لوحة السوبر أدمن = تصعيد صلاحيات كامل
أسماء البطولات والمالكين والمواسم كانت تُحقن في `innerHTML` بلا تهريب. والمنظّم يملك تعديل اسم بطولته. فيكفيه اسم مثل `<img src=x onerror=...>` ليُنفَّذ كوده في متصفح السوبر أدمن: يقرأ كل طلبات الاشتراك بكلمات مرورها، وينشئ ويحذف أي شيء.
**✅ أُصلح:** دالّة `esc()` على كل نص قادم من Firestore في `superadmin.js` (16 موضعاً).

### 3. إصلاحات لوحة السوبر أدمن لا تصل للمتصفح أبداً
`firebase.json` يخدم ملفات JS/CSS بكاش **سنة كاملة `immutable`**، و`superadmin.js` و`superadmin.css` و`viewer.css` و`match-core.js` كانت **بلا رقم إصدار**. أي أن الإصلاح رقم 2 نفسه لم يكن ليصل.
**✅ أُصلح:** كل الصفحات الثماني على `?v=339` (58 رابطاً)، و`sw.js` على `batolat-v339`.

### 4. المنظّم يرفع حدود باقته بنفسه
`limits` (عدد الفرق واللاعبين) على مستند البطولة، والمنظّم يعدّل المستند. فسطر واحد في DevTools (`limits:{maxTeams:0}`) = بلا حدود.
**✅ أُصلح** في القواعد: `limits` لا يتغيّر إلا من السوبر أدمن.

## 🟠 عالية

### 5. الذهاب والإياب في الإقصاء: الحسم يعامل كل مباراة وحدها
- **الذهاب المتعادل 1-1** كان يُمنع إنهاؤه ويُفرض عليه وقت إضافي تلقائي.
- **الإياب 1-1 بعد ذهاب 2-0** كان يُمنع إنهاؤه، والمتأهّل محسوم بالمجموع.
- **الإياب 0-1 بعد ذهاب 1-0** (مجموع متعادل) كان يُنهى بلا حسم ويُمنع زر الركلات، فيعلق التأهّل.

**✅ أُصلح:** دالّة واحدة `_koNeedsDecider` تحسب المجموع بنفس منطق `_autoAdvanceWinner` حرفياً، وتستعملها الأماكن الخمسة: الأزرار، الإضافي التلقائي، رسالة نهاية الوقت، حارس الإنهاء، وحارس الركلات.

### 6. إلغاء «إنهاء المباراة» يجمّد المباراة
الساعة والحفظ التلقائي كانا يُوقَفان **قبل** نافذة التأكيد. فإن ضغط المنظّم «إلغاء» (أو رُفض الإنهاء لتعادل إقصاء) بقيت مباراة جارية بلا ساعة ولا حفظ.
**✅ أُصلح:** الإيقاف صار بعد التأكيد.

### 7. كسر التعادل الثلاثي اعتباطي
كان الترتيب بمقارن زوجي. فمع ثلاثة فرق متساوية بمواجهات دائرية (أ>ب، ب>ج، ج>أ) يصير المقارن متناقضاً، فيخرج ترتيب يتغيّر بترتيب المدخلات، وقد يختلف بين المنظّم والجمهور.
**✅ أُصلح:** `StandingsCore.rank` يطبّق **دوري مصغّراً** بين كل المتساوين (أسلوب FIFA/UEFA)، ثم يعيد القواعد على أي مجموعة فرعية بقيت متساوية. ولفريقين النتيجة مطابقة للسابق. ووُصل بخمسة مواضع: الجدول العام (جمهور + إدارة)، المجموعات (جمهور + all-fixes)، ومحرّر توزيع المجموعات. وهذا الأخير كان يتجاهل قواعد الحسم التي اختارها المنظّم تماماً.

### 8. انتهاء رابط التسليم كان شكلياً
الـ 14 يوماً كانت تُفحص في الصفحة فقط، والمستند (وفيه كلمة مرور الإدارة) يبقى مقروءاً للأبد بـ `getDoc` مباشر.
**✅ أُصلح:** الخادم يرفضه بعد الانتهاء، والصفحة تعرض «انتهت الصلاحية» بدل «مشكلة اتصال».

### 9. أي زائر يقطع بث كل المشاهدين
مقاعد المشاهدين كانت قابلة للسرد والحذف والكتابة فوق `answer` للجميع.
**✅ أُصلح:** السرد وكتابة `answer` للمذيع وحده، والإنشاء بـ `offer` فقط وبحجم محدود. ومعرّف المقعد العشوائي لا يعرفه إلا صاحبه.

## ⚠️ لم يُغيَّر عمداً — يحتاج قرارك
- **ترتيب الإيقافات (ر-4):** حقل `endTime` موجود في البث، لكنه يُختم بوقت **الإدخال** عند إدخال نتيجة متأخرة، فاعتماده قد يفسد ترتيباً صحيحاً اليوم. الأسلم: عدّل تاريخ المباراة المؤجّلة عند لعبها.
- **صور اللاعبين في Storage:** أي منظّم مسجّل يستطيع حذف صور بطولة غيره، لأن المسار `players/{teamId}/...` لا يحوي معرّف البطولة. الحل: مسار جديد `leagues/{lid}/players/...` للرفع الجديد. وهذا تغيير في الرفع يحتاج تجربة.
- **صفحة الجمهور:** أسماء الفرق واللاعبين تُحقن بلا تهريب في مواضع عدة. لا يكتبها إلا المنظّم فالخطر محدود، لكنها تستحق جولة مستقلة.
- **Cloud Functions، Custom Claims، معاينة الروابط الديناميكية:** ما زالت أعلى التوصيات عائداً (التقرير السابق ت-1 وت-3 وت-ج).

## 🧪 الاختبارات — جديد في هذه النسخة
مجلد `tests/` (مستبعد من النشر في `firebase.json`):

```bash
cd tests
npm install
npm run test:logic   # المنطق الرياضي — ثوانٍ، بلا إنترنت
npm run test:rules   # قواعد Firestore على المحاكي الرسمي (يحتاج Java)
```

**قاعدة ذهبية:** لا تنشر `firestore.rules` قبل أن يمرّ `npm run test:rules`. الخلل رقم 1 أعلاه كان سيُسقط كل بطولة جديدة، ولم يكشفه إلا المحاكي.

## قبل النشر
1. تأكّد من وجود `admins/{uid}` بـ `role: "superadmin"` لحسابك (كما في v338).
2. `cd tests && npm install && npm test`
3. `firebase deploy --only firestore:rules,hosting`
