# ما عليك عمله بنفسك — القائمة النهائية

> اختصرت كل ما كان مطلوباً منك إلى **خطوة واحدة إجبارية**.
> الباقي أتمتُّه أو صار زرّاً داخل لوحتك.

# ✅ الخطوة الوحيدة الإجبارية: نشر قواعد Firestore

كل ما تواجهه اليوم — رسالة «لا توجد صلاحية» في رابط التسليم، وعدم دخولك لأي بطولة من لوحتك — سببه **القواعد المنشورة حالياً**، لا حسابك.

## لماذا؟

القواعد القديمة تعرف السوبر أدمن بطريقة ملتوية:

> «كل مستخدم مسجّل دخول **وليس له سجلّ في `leagueAdmins`** = سوبر أدمن»

فتسقط صلاحيتك فوراً لو وُجد مستند `leagueAdmins` باسم حسابك.

القواعد الجديدة تعرفه صراحةً:

> `admins/{uid}.role == 'superadmin'`

وهو **نفس ما يفحصه كود الدخول عندك أصلاً** — فتتطابق الواجهة مع الخادم بدل أن يفترض كل منهما شيئاً مختلفاً. ولن تسقط صلاحيتك مهما امتلكت بطولات.

## الطريقة (أ) — من المتصفح · دقيقتان

1. افتح https://console.firebase.google.com
2. اختر مشروع **footblle2**
3. القائمة اليسرى: **Build → Firestore Database**
4. تبويب **Rules** بالأعلى
5. **احذف كل المحتوى الظاهر**، والصق محتوى ملف `firestore.rules` من الحزمة
6. اضغط **Publish**

## الطريقة (ب) — من الطرفية · أمر واحد

جهّزت لك `firebase.json` و`.firebaserc` داخل الحزمة، ومعرّف مشروعك مضبوط سلفاً:

```bash
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules
```

## للتراجع الفوري لو حدث أي خلل

**Firestore Database → Rules → History** ← اختر أي إصدار سابق ← **Restore**.
التراجع فوري ولا يفقد أي بيانات.

# 🩺 كيف تتأكد أن كل شيء تمام

أضفت زرّ **«🩺 فحص»** في الشريط العلوي للوحة السوبر أدمن.

اضغطه بعد النشر — يفحص بنفسه:
- سجلّ صلاحيتك (`admins/{uid}`)
- وجود سجلّ منظّم متعارض
- **ويجرّب إنشاء رابط تسليم حقيقي ثم يحذفه** — أي يختبر المسار نفسه الذي اشتكيت منه، لا يظنّه

ويعطيك الخلاصة مباشرة: إما «🎉 كل شيء سليم — لا إجراء مطلوب»، أو يقول لك بالضبط ماذا ينقص.

---

# ❌ ما لم تعد بحاجة إليه

| الخطوة | الحالة |
|---|---|
| إنشاء حساب سوبر أدمن | **ملغاة** — موجود عندك، ودليله أنك تدخل اللوحة اليوم |
| إنشاء `admins/{uid}` يدوياً | **ملغاة** — لنفس السبب |
| حذف `leagueAdmins/{uid}` | **اختيارية** — القواعد الجديدة لا تتأثر به |
| البحث اليدوي عن سبب الخطأ | **ملغاة** — زرّ الفحص يفعلها |

# 📋 تحسينات اختيارية (لا تمنع شيئاً اليوم)

هذه لا علاقة لها بمشكلتك الحالية — نفّذها متى شئت.

## 1. خادم TURN — ١٠–٢٠٪ من مشاهدي البث لا يصلهم البث

المشاهد خلف NAT متماثل أو شبكة جوال مقيّدة لا يتصل إطلاقاً (فشل كامل لا تقطّع).

1. اشترك في مزوّد TURN (Metered أو Twilio)
2. افتح `broadcaster.html`، ابحث عن `TURN_CONFIG` (نحو السطر 605)
3. أزل `//` من الأسطر الثلاثة، واستبدل `YOUR_USER` و`YOUR_CRED`
4. **تحقق:** ابثّ واختبر بمشاهد على بيانات الجوال — لا واي فاي

## 2. صورة معاينة الروابط على واتساب

`og:image` مسار نسبي فلا تظهر صورة إطلاقاً.

1. افتح `league-viewer.html` السطر 18 تقريباً
2. غيّر `content="icon-512.png"` إلى `content="https://نطاقك/icon-512.png"`
3. **تحقق:** https://developers.facebook.com/tools/debug ← الصق رابط بطولة ← **Scrape Again**

## 3. كلمات المرور المخزّنة نصّاً

`subscribe.html` يخزّنها بلا تشفير ويرسلها في واتساب. الحل الصحيح نقل إنشاء الحسابات إلى Cloud Functions.

**إجراء فوري ريثما تفعل:** احذف حقل `password` من مستندات `subRequests` القديمة من Firestore Console.
